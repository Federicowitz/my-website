15 | Ereditarietà: eroi e nemici

Quando più tipi condividono una parte del comportamento, una classe base può raccogliere ciò che hanno in comune. Le derivate aggiungono le proprie caratteristiche.

Prerequisito: capitolo 14. Nel laboratorio trovi esempi più piccoli prima del gioco completo.

Base e derivata

Un Mago è un Personaggio; un Goblin è un Personaggio. Con class Mago : public Personaggio esprimiamo una relazione pubblica “è un”. La base conserva i dati comuni e le regole della vita. La derivata aggiunge, per esempio, mana o frecce. Non copiamo gli stessi campi in ogni derivata.

Accesso e costruzione

Una derivata non può accedere direttamente ai membri private della base: usa la sua interfaccia. public è accessibile dall’esterno; protected consente l’accesso anche nelle derivate. Negli esempi manteniamo privati i dati e usiamo metodi pubblici, così una derivata non può aggirare le regole della vita.

La parte base si costruisce prima della parte derivata. In Mago(string n) : Personaggio(n) {} la lista di inizializzazione sceglie il costruttore della base. È diversa dal dichiarare la relazione tra classi, anche se entrambe le scritture usano due punti.

Ereditarietà o composizione?

Un Arciere è un Personaggio, ma ha un Equipaggiamento. L’arma è un membro dell’Arciere, non una sua classe base. Scegli la relazione in base al significato del modello, non soltanto per evitare di riscrivere righe.

Cosa non abbiamo ancora introdotto

Chiamare lancia sul Mago e tira sull’Arciere usa direttamente due tipi conosciuti. Il polimorfismo dinamico arriverà nella prossima lezione con virtual e override: l’ereditarietà, da sola, non rende ogni chiamata virtuale.

Ogni esempio è indipendente. Crea un file main.cpp e copia un programma completo alla volta: non incollare più main nello stesso file. Compila con g++ -std=c++17 -Wall -Wextra -pedantic main.cpp -o gioco. Avvia .\gioco.exe in PowerShell oppure ./gioco su macOS/Linux. Salva e ricompila dopo ogni modifica.

Negli esempi brevi usiamo using namespace std; per scrivere cout, string e vector senza ripetere std::. Non sostituisce gli include. Nei progetti più grandi e negli header è preferibile limitare questa direttiva, per evitare nomi ambigui.

ESEMPIO 15

Esempio completo

Leggi il programma, prevedi il risultato e soltanto dopo eseguilo.

main.cpp · programma completo

#include <iostream>
#include <string>
using namespace std;

class Personaggio {
private:
  string nome;
  int vita = 100;
public:
  Personaggio(string n) : nome(n) {}
  string getNome() const { return nome; }
  int getVita() const { return vita; }
  bool vivo() const { return vita > 0; }
  void subisciDanno(int n) {
    if (n <= 0) return;
    vita -= n;
    if (vita < 0) vita = 0;
  }
};

class Mago : public Personaggio {
public:
  Mago(string n) : Personaggio(n) {}
};

int main() {
  Mago mago("Aria");
  mago.subisciDanno(20);
  cout << mago.getNome() << ": " << mago.getVita() << '\n';
}

Risultato atteso

Aria: 80

Modifica tu. Aggiungi un Goblin derivato. Indica quali dati e regole collocheresti nella base e quali nelle due derivate.

Segui l’esecuzione

Il Mago contiene una parte Personaggio. Il costruttore della base riceve Aria. Il metodo ereditato applica il danno senza esporre direttamente la vita privata.
