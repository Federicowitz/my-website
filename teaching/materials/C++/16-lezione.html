16 | Polimorfismo: un gruppo di personaggi

Un unico punto di chiamata può produrre comportamenti diversi, scelti in base al tipo effettivo dell’oggetto: un Mago lancia un incantesimo, un Arciere scocca una freccia.

Prerequisito: capitolo 15. Nel laboratorio trovi esempi più piccoli prima del gioco completo.

Una stessa interfaccia

Una funzione che riceve un Personaggio per riferimento può usare la sua interfaccia senza conoscere ogni tipo derivato. Per ottenere una scelta dinamica il metodo della base deve essere virtual. La derivata lo ridefinisce con la stessa firma; override chiede al compilatore di verificarlo.

Tre parole da leggere

virtual
Abilita la scelta dinamica della funzione membro.
override
Verifica che il metodo della derivata sostituisca davvero un metodo virtuale della base.
Metodo virtuale puro
Con = 0 richiede una realizzazione nelle classi concrete; una classe con funzioni virtuali pure non implementate è astratta e non si può istanziare.

Const e tipi dei parametri fanno parte dei dettagli da far corrispondere. Non confondere override con sovraccaricare il nome usando parametri diversi.

Oggetti, riferimenti e copie

Attraverso riferimenti e puntatori conserviamo il collegamento all’oggetto derivato. Copiarlo in un Personaggio per valore elimina la parte derivata dalla nuova copia: è object slicing. Per una squadra eterogenea il laboratorio usa un vector di puntatori a oggetti locali già vivi, senza new o delete. Gli indirizzi non devono sopravvivere agli oggetti.

Il distruttore virtuale

virtual ~Personaggio() = default; dichiara un distruttore virtuale e lascia al compilatore la sua implementazione ordinaria. È necessario per poter eliminare correttamente un oggetto derivato tramite un puntatore alla base con il normale delete. I nostri esempi non possiedono gli oggetti tramite i puntatori: gli oggetti locali vengono distrutti automaticamente alla fine del main.

Ogni esempio è indipendente. Crea un file main.cpp e copia un programma completo alla volta: non incollare più main nello stesso file. Compila con g++ -std=c++17 -Wall -Wextra -pedantic main.cpp -o gioco. Avvia .\gioco.exe in PowerShell oppure ./gioco su macOS/Linux. Salva e ricompila dopo ogni modifica.

Negli esempi brevi usiamo using namespace std; per scrivere cout, string e vector senza ripetere std::. Non sostituisce gli include. Nei progetti più grandi e negli header è preferibile limitare questa direttiva, per evitare nomi ambigui.

ESEMPIO 16

Esempio completo

Leggi il programma, prevedi il risultato e soltanto dopo eseguilo.

main.cpp · programma completo

#include <iostream>
#include <string>
using namespace std;

class Personaggio {
public:
  virtual string azione() const { return "Colpo normale"; }
  virtual ~Personaggio() = default;
};
class Mago : public Personaggio {
public:
  string azione() const override { return "Incantesimo"; }
};
class Arciere : public Personaggio {
public:
  string azione() const override { return "Freccia"; }
};

void turno(const Personaggio& p) { cout << p.azione() << '\n'; }

int main() {
  Mago mago;
  Arciere arciere;
  turno(mago);
  turno(arciere);
}

Risultato atteso

Incantesimo
Freccia

Modifica tu. Aggiungi un Guerriero senza cambiare turno. Poi confronta il risultato con una funzione che riceve Personaggio per valore.

Segui l’esecuzione

turno usa la stessa espressione p.azione() due volte. Il riferimento conserva il tipo effettivo: la prima chiamata raggiunge Mago, la seconda Arciere.
