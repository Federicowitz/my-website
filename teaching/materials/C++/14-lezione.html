14 | Classi, oggetti e incapsulamento

Raggruppare i dati non basta quando vogliamo imporre regole. Una classe può esporre operazioni e controllare come cambia il proprio stato.

Prerequisito: capitolo 13. Nel laboratorio trovi esempi più piccoli prima del gioco completo.

Classe e oggetto

Una classe definisce un tipo, con dati e funzioni membro chiamate metodi. Un oggetto è una sua istanza concreta. Due personaggi creati dalla stessa classe hanno dati indipendenti: cambiare la vita di uno non cambia l’altro.

Private, public e incapsulamento

Con private i dati sono accessibili direttamente dai membri della classe, non dal main. Con public rendiamo disponibili le operazioni da chiamare. L’incapsulamento permette di mantenere regole come “vita non negativa”: il codice esterno chiama subisciDanno invece di scrivere un numero qualsiasi nella vita.

Entrambe possono avere dati, metodi e costruttori. Non è corretto dire che struct contiene soltanto dati mentre class può contenere funzioni: qui scegliamo struct per i primi raggruppamenti e class quando vogliamo evidenziare un’interfaccia con regole.

Costruttore e metodi const

Il costruttore si chiama come la classe e non dichiara un tipo di ritorno. Prepara l’oggetto durante la sua creazione. Un metodo con const dopo le parentesi promette di non modificare i normali membri dell’oggetto: è utile per getNome e getVita. Inizializziamo la vita nel campo e assegniamo il nome nel costruttore; il laboratorio introduce poi la lista di inizializzazione.

Ogni esempio è indipendente. Crea un file main.cpp e copia un programma completo alla volta: non incollare più main nello stesso file. Compila con g++ -std=c++17 -Wall -Wextra -pedantic main.cpp -o gioco. Avvia .\gioco.exe in PowerShell oppure ./gioco su macOS/Linux. Salva e ricompila dopo ogni modifica.

Negli esempi brevi usiamo using namespace std; per scrivere cout, string e vector senza ripetere std::. Non sostituisce gli include. Nei progetti più grandi e negli header è preferibile limitare questa direttiva, per evitare nomi ambigui.

ESEMPIO 14

Esempio completo

Leggi il programma, prevedi il risultato e soltanto dopo eseguilo.

main.cpp · programma completo

#include <iostream>
#include <string>
using namespace std;

class Personaggio {
private:
  string nome;
  int vita = 100;
public:
  Personaggio(string nuovoNome) { nome = nuovoNome; }
  string getNome() const { return nome; }
  int getVita() const { return vita; }
  bool vivo() const { return vita > 0; }
  void subisciDanno(int danno) {
    if (danno <= 0) return;
    vita -= danno;
    if (vita < 0) vita = 0;
  }
};

int main() {
  Personaggio eroe("Brina");
  eroe.subisciDanno(25);
  cout << eroe.getNome() << ": " << eroe.getVita() << '\n';
}

Risultato atteso

Brina: 75

Modifica tu. Prova danni negativi, zero e maggiori della vita. Motiva perché le regole vanno applicate dentro il metodo, anche se chi lo chiama sbaglia.

Segui l’esecuzione

Il costruttore assegna il nome. Il campo vita parte da 100. Il metodo modifica lo stato; i getter lo leggono. eroe.vita dal main sarebbe un accesso vietato.
