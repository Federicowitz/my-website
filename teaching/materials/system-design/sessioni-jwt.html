Come fa il server a ricordare il login?

Quando inseriamo username e password, il server verifica le credenziali.

Ma che cosa succede dopo?

Se apriamo un'altra pagina del sito, non dobbiamo effettuare nuovamente il login. Eppure HTTP è un protocollo stateless: una richiesta non conserva automaticamente la memoria delle precedenti.

Come fa quindi il server a sapere chi siamo?

Esistono diverse soluzioni, tra cui le sessioni lato server e l'utilizzo di token JWT.

Soluzione A — Autenticazione basata su sessioni

Seguiamo il login di uno studente.

  1. L'utente effettua il login.
  2. Il server verifica le credenziali e crea una sessione.
  3. La sessione viene registrata in un archivio.
  4. Il browser riceve un cookie contenente un identificatore casuale della sessione.
  5. A ogni richiesta successiva, il browser invia il cookie.
  6. Il server consulta l'archivio per verificare a chi appartiene la sessione e se è ancora valida.

Il server deve conservare informazioni relative alle sessioni, ma queste possono stare in un archivio condiviso come Redis.

Questo si collega direttamente alla lezione sui server stateless: non è necessario memorizzare le sessioni nella memoria locale di ciascun server applicativo.

Soluzione B — Autenticazione con JWT

In questo caso:

  1. L'utente effettua il login.
  2. Il server verifica le credenziali e genera un JWT firmato.
  3. Il client riceve il token.
  4. Alle richieste successive presenta il token.
  5. Il server verifica la firma, la scadenza e le altre condizioni di validità.
  6. Se i controlli hanno esito positivo, la richiesta può proseguire.

Il JWT contiene delle informazioni chiamate claims, come l'identificatore dell'utente, la scadenza e l'emittente.

Il vantaggio è che il server può verificare il token senza consultare ogni volta un archivio di sessioni.

Ma c'è uno svantaggio importante: se si vuole revocare immediatamente un JWT già emesso, la gestione può diventare più complessa.

JWT e cookie non sono alternative dirette. JWT è un formato di token; cookie è un meccanismo con cui il browser conserva e trasmette informazioni. Anche un JWT può essere trasportato in un cookie.

Con un JWT trasmesso tramite Authorization: Bearer <token>, il possesso del token consente di presentarlo. La API controlla firma, algoritmo previsto, emittente, destinatario e scadenza. Il payload firmato è leggibile. Per cancellare una prenotazione occorre anche verificare che appartenga allo studente o che il suo ruolo consenta di intervenire.
