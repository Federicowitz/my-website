Identità e permessi

Authentication e Authorization

Due concetti fondamentali della sicurezza sono l'autenticazione e l'autorizzazione.

Authentication: verifica l'identità del soggetto.

Risponde alla domanda: Chi sei?

Authorization: determina le operazioni che quel soggetto può compiere.

Risponde alla domanda: Che cosa puoi fare?

Per esempio, uno studente può effettuare il login su EventiScuola, ma non deve poter modificare il prezzo di un evento.

È autenticato, ma non autorizzato a eseguire quell'operazione.

Metodi e tecnologie di autenticazione

Sessioni e cookie

Una tecnica tradizionale prevede che il server crei una sessione dopo il login.

Il browser conserva un identificatore di sessione, spesso attraverso un cookie.

Nelle richieste successive, il server utilizza tale identificatore per riconoscere l'utente.

I cookie possono essere configurati con proprietà di sicurezza come Secure, HttpOnly e SameSite.

API Key

Una API key è una chiave associata a un client o a un'applicazione.

Può essere usata per identificare e controllare l'accesso alle API, ma non sempre rappresenta un'identità utente individuale.

Bearer Token e JWT

Con l'autenticazione basata su token, il client invia una credenziale a ogni richiesta.

Un formato utilizzato è JWT (JSON Web Token).

Un JWT può contenere informazioni come identificatore dell'utente, scadenza e altri attributi.

Un JWT firmato consente di verificare che il contenuto non sia stato modificato senza autorizzazione. Non è però necessariamente cifrato: le informazioni contenute possono essere leggibili.

Access Token e Refresh Token

Un access token viene utilizzato per accedere alle risorse ed è generalmente di durata relativamente breve.

Un refresh token permette di richiedere nuove credenziali di accesso senza ripetere ogni volta il login completo.

La conservazione sicura di questi token è importante. I cookie HttpOnly possono mitigare determinati rischi legati all'accesso dei token tramite JavaScript, ma richiedono adeguate protezioni anche contro CSRF.

OAuth 2.0

OAuth 2.0 è un framework di autorizzazione delegata.

Permette, per esempio, di concedere a un'applicazione l'accesso limitato a determinate risorse senza comunicarle direttamente la password principale.

OpenID Connect

OpenID Connect (OIDC) aggiunge un livello di identità a OAuth 2.0.

È utilizzato in molte soluzioni di accesso federato.

Single Sign-On

Il Single Sign-On (SSO) permette di autenticarsi presso un sistema di identità e accedere successivamente a più applicazioni senza ripetere ogni volta l'intero processo di login.

In contesti aziendali vengono utilizzati anche protocolli come SAML.

Modelli di autorizzazione

Dopo aver riconosciuto l'utente, bisogna stabilire a quali risorse possa accedere.

Modello Funzionamento Esempio
RBAC Permessi assegnati in base ai ruoli Amministratore, organizzatore, studente
ABAC Permessi basati su attributi e condizioni Un organizzatore modifica solo eventi della propria scuola
ACL Elenco di autorizzazioni associato alla risorsa Uno specifico documento condiviso con determinati utenti

I sistemi possono combinare questi modelli.

Una regola generale è il principio del minimo privilegio: ogni soggetto deve ricevere soltanto le autorizzazioni necessarie a svolgere le proprie attività.

Proteggere le API

Un'applicazione accessibile da Internet deve gestire tentativi di abuso e attacco.

Rate Limiting

Il rate limiting limita il numero di richieste consentite in un determinato intervallo.

Un'API potrebbe consentire, ad esempio, 100 richieste al minuto per utente.

Una tecnica comune è il token bucket, che permette brevi picchi mantenendo controllata la frequenza media.

Injection

Gli attacchi di injection sfruttano input non gestiti correttamente per alterare l'interpretazione di comandi o query.

Per prevenirli si utilizzano, tra le altre misure, query parametrizzate, validazione degli input e privilegi minimi.

CORS

CORS (Cross-Origin Resource Sharing) è un meccanismo del browser che regola quando una pagina web può leggere risposte provenienti da origini differenti.

Non è un sistema generale di autenticazione né una barriera valida contro qualsiasi client HTTP.

CSRF

CSRF (Cross-Site Request Forgery) consiste nell'indurre il browser di un utente autenticato a inviare richieste indesiderate.

Si contrasta con opportune protezioni, tra cui token anti-CSRF e configurazioni adeguate dei cookie.

WAF e VPN

Un WAF (Web Application Firewall) analizza traffico HTTP e può bloccare determinate richieste malevole.

Una VPN (Virtual Private Network) può permettere di limitare l'accesso a servizi interni a utenti o dispositivi autorizzati.

Queste misure sono complementari: nessuna, da sola, rende automaticamente sicura l'intera applicazione.
