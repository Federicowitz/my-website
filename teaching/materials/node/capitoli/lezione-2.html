LEZIONE 02 · Fondamenti

Installazione e ambiente

Prima di iniziare: le parole della lezione

LTS
Long-Term Support: linea di versioni mantenuta nel tempo con correzioni e aggiornamenti di sicurezza.
Terminale, shell e CLI
Il terminale mostra l’interfaccia testuale; la shell, per esempio PowerShell, interpreta i comandi; una CLI è un programma utilizzabile tramite comandi.
PATH e directory di lavoro
PATH è l’elenco di cartelle in cui la shell cerca gli eseguibili. La directory di lavoro è la cartella da cui un comando viene eseguito.
Editor e REPL
Un editor modifica i file di codice. Una REPL legge un’espressione, la esegue, stampa il risultato e attende il comando successivo.

Definizioni complete: dal termine al comportamento

Terminale, shell e directory
Il terminale mostra una sessione; la shell interpreta i comandi. La directory corrente determina come si risolvono molti percorsi relativi. L’editor modifica il sorgente, mentre node esegue il file salvato: un file aperto nell’editor non viene eseguito automaticamente.
PATH e installazione
PATH è l’elenco di directory in cui la shell cerca i programmi. “node non riconosciuto” riguarda spesso installazione o PATH, non la sintassi del tuo script. Verifica node --version e npm --version nello stesso terminale che userai per il corso.
Versione e riproducibilità
La versione del runtime stabilisce quali API sono disponibili. Registra la versione usata e scegli una release supportata compatibile con il progetto. Una versione più recente sul tuo computer non garantisce che il computer di un compagno esegua lo stesso codice.

Verifica la comprensione

Il file esiste ma node non lo trova: cosa controlli?

Leggi la spiegazione

Directory corrente, percorso passato al comando, nome ed estensione del file; poi la versione del runtime.

Installa una versione LTS attualmente supportata dal sito ufficiale di Node.js. Il corso originale mostra versioni 14 e 16: sono riferimenti storici, non versioni da installare oggi. Usa un editor come Visual Studio Code; le estensioni sono facoltative.

node --version
npm --version
mkdir corso-node
cd corso-node

Crea index.js e lancialo:

node index.js

Esempio aggiuntivo: per aprire la console interattiva basta eseguire node, scrivere 2 + 2 e uscire con .exit. Controllo: se node non viene riconosciuto, riapri il terminale e verifica l'installazione e il PATH.

Chi fa cosa, e perché

L’installer rende disponibile node; npm è il gestore di pacchetti normalmente distribuito insieme a Node. Visual Studio Code serve a scrivere e salvare i file, mentre il terminale avvia il runtime. Scrivere codice nell’editor non lo esegue: occorre salvarlo e passare il file a node.

Alcune estensioni dell’editor propongono frammenti di codice, detti snippet. Sono facoltative e non installano né Node né Express. Tieni aperta nel terminale la cartella che contiene il tuo script: un file esistente in un’altra cartella può risultare “non trovato”.

Un altro esempio guidato

# PowerShell: un comando per riga
node --version
npm --version
Get-Location
node -e "console.log('Installazione riuscita')"

Come leggerlo e risultato atteso. --version chiede la versione; Get-Location mostra la cartella attuale; -e esegue il breve programma passato come testo e stampa Installazione riuscita. Per avviare un file con spazi nel nome usa node "primo esempio.cjs".

Pratica attuale e precisazioni. Scegli una linea LTS ancora supportata dalla tabella ufficiale delle release. Le versioni 14 e 16 della registrazione sono fuori supporto. Non occorre installare pacchetti globali per iniziare.

Prova tu. Apri una nuova shell dopo l’installazione e ripeti i controlli. Se node funziona ma npm è bloccato da PowerShell, prova npm.cmd --version prima di modificare impostazioni del sistema.
