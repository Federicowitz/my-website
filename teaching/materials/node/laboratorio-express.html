Il punto di partenza

Qui assumiamo chiari metodo, URL, status e corpo della richiesta dai primi esempi HTTP e dai form e metodi. L’installazione appartiene alla nuova cartella lab-express: non occorre cambiare i progetti precedenti. Usa una versione recente di Node.js compatibile con Express 5; verifica con node --version. Dopo ogni sostituzione di server.cjs ferma con Ctrl+C e riavvia.

TAPPA 1

Express: una sola rotta GET

Obiettivo: riconoscere ciò che già sappiamo. Express è un pacchetto che gira sopra Node e ci permette di dichiarare le rotte. L’HTTP non cambia: restano metodo, percorso, status, header e corpo.

Crea una cartella nuova lab-express. Qui, per la prima volta, installiamo un pacchetto:

npm init -y
npm install express@5

server.cjs · primo server Express

const express = require('express');
const app = express();

const IP = '127.0.0.1';
const PORT = 3000;

app.get('/', (req, res) => {
  res.send('Ciao da Express!');
});

app.listen(PORT, IP, () => {
  console.log(`Server Express su http://${IP}:${PORT}`);
});
node server.cjs

app.get registra la coppia GET + /. res.send conclude la risposta; il normale stato di successo è 200. IP e PORT conservano il significato dei laboratori precedenti.

Prova nel secondo terminale

curl.exe -i http://127.0.0.1:3000/
curl.exe -i http://127.0.0.1:3000/altra

Risultato atteso. La home risponde 200; /altra risponde 404. Le richieste non gestite ricevono per impostazione predefinita un 404. Express non genera automaticamente un 405 solo perché lo stesso percorso esiste con un altro metodo.

Tocca a te. Cambia PORT, riavvia e visita l’indirizzo stampato. Poi ripristina 3000. Individua la parte del vecchio if che ora viene espressa con app.get.

TAPPA 2

Express: HTML, testo e JSON

Stesse tre risposte, sintassi più breve. Il frontend resta HTML con due link: nessuno script e nessun CSS.

server.cjs · tre rotte

const express = require('express');
const app = express();

const IP = '127.0.0.1';
const PORT = 3000;

app.get('/', (req, res) => {
  res.send('<h1>Home</h1><p><a href="/saluto">Saluto</a></p><p><a href="/info">JSON</a></p>');
});

app.get('/saluto', (req, res) => {
  res.type('text/plain').send('Ciao dalla rotta /saluto!');
});

app.get('/info', (req, res) => {
  res.json({ corso: 'Node.js', framework: 'Express' });
});

app.use((req, res) => {
  res.status(404).type('text/plain').send('Pagina non trovata.');
});

app.listen(PORT, IP, () => {
  console.log(`Server Express su http://${IP}:${PORT}`);
});

res.send con una stringa usa normalmente text/html; per il testo semplice impostiamo il tipo con res.type. res.json converte l’oggetto e imposta il tipo JSON. La funzione finale con app.use risponde 404 alle richieste che non hanno trovato una rotta: per questo sta in fondo.

Risultato atteso. I link della home navigano a /saluto e /info. Network mostra rispettivamente text/plain e application/json. /sconosciuta mostra il nostro 404.

Tocca a te. Aggiungi app.get per /classe con un oggetto JSON. Inseriscila prima della funzione finale che risponde 404.

TAPPA 3

Express: riprendere il form POST

Ripetiamo il form del laboratorio 2. Prima dovevamo raccogliere data/end e interpretare il corpo. Qui express.urlencoded prepara i campi e li rende disponibili in req.body.

server.cjs · form completo

const express = require('express');
const app = express();

const IP = '127.0.0.1';
const PORT = 3000;

// Interpreta i campi inviati dai normali form HTML.
app.use(express.urlencoded({ extended: false }));

app.get('/', (req, res) => {
  res.send(`<!doctype html>
<html lang="it">
<head>
  <meta charset="utf-8">
  <title>Laboratorio Node.js</title>
</head>
<body>
  <h1>Come ti chiami?</h1>
  <form action="/saluto" method="post">
    <label>Nome: <input name="nome" required></label>
    <button type="submit">Invia</button>
  </form>
</body>
</html>`);
});

app.post('/saluto', (req, res) => {
  let nome = '';
  if (req.body && typeof req.body.nome === 'string') {
    nome = req.body.nome.trim();
  }
  if (nome === '') {
    res.status(400).type('text/plain').send('Scrivi un nome.');
    return;
  }
  res.type('text/plain').send('Ciao, ' + nome + '!');
});

app.use((req, res) => {
  res.status(404).type('text/plain').send('Pagina non trovata.');
});

app.listen(PORT, IP, () => {
  console.log(`Server Express su http://${IP}:${PORT}`);
});

Una funzione inserita con app.use che prepara la richiesta prima della rotta è chiamata middleware. In questo esempio il parser deve stare prima di app.post. Il controllo sul tipo stringa evita di chiamare trim su un dato inatteso; se req.body manca, il nome risulta vuoto e rispondiamo 400. Anche qui rispondiamo in text/plain, così il nome è mostrato come testo.

Prova nel secondo terminale

curl.exe -i --data-urlencode "nome=Ada Lovelace" http://127.0.0.1:3000/saluto
curl.exe -i -d "nome=" http://127.0.0.1:3000/saluto

Risultato atteso. Nome valido → 200 e saluto; nome vuoto → 400. GET /saluto riceve 404 in questo esempio perché abbiamo dichiarato soltanto POST /saluto; non abbiamo scritto un gestore 405.

Tocca a te. Aggiungi un campo classe e restituiscilo come testo. Confronta il codice con la raccolta del body nel laboratorio precedente e indica quale lavoro è stato affidato al middleware.

Prima di continuare

Riscrivi una piccola rotta prima con http.createServer, poi con app.get: per entrambe indica metodo, percorso, stato e tipo del corpo. I concetti restano gli stessi, anche se il framework si occupa di parte del lavoro.

Al termine ferma il server con Ctrl + C. Se vedi EADDRINUSE, la porta è già occupata: ferma la tua versione precedente prima di avviarne un’altra. Salva il lavoro prima di sostituire i file con la versione della tappa successiva.
